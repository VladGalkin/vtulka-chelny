# Инструкции для Codex / AI-агентов

Прочти `README.md`, `docs/README.md`, `docs/01_Project/Vision.md`, `docs/02_Requirements/OpenQuestions.md` перед предложениями по реализации.

## Правила работы

1. **Не выдумывай бизнес-факты.** Отделяй согласованные требования от предположений и открытых вопросов.
2. **Не меняй границы MVP без явного решения владельца проекта.** Приоритеты: P0 — базовый сайт-каталог и заявки; P1 — расширения; P2 — отложенное.
3. **Сначала план, затем код.** Перед существенными изменениями опиши затронутые файлы и последствия.
4. **Объясняй решения на русском языке.** Проект учебно-практический, разработчик должен понимать изменения.
5. **Не встраивай секреты.** Не считывай и не публикуй токены, `.env`, данные реальных клиентов и файлы заказчиков.
6. **Не подключай ненужные зависимости.** Каждую новую технологию обосновывай.
7. **Не утверждай, что тесты прошли, если их не запускал.** В отчёте перечисляй выполненные команды и результат.
8. **Не выполняй деплой и необратимые действия без явного разрешения.**
9. **Фиксируй важные решения в документах**, а не только в сообщении чата.
10. **Не коммить автоматически**, если об этом не попросили. Передай автору список изменённых файлов и предложения по проверке.
